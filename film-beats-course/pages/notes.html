Failure modes & sources

Failure modes

Common ways each week goes wrong, worth rereading if a session isn't working.

  • Collecting instead of finishing. Sampling is pleasurable; arranging isn't. Forty pads and no bounce means the week failed.
  • Over-processing. Film audio is already textured. Vinyl Sim on top of 1970s optical-track hiss is mud.
  • Grandmother in the dialogue range. The most common way this genre fails — see Week 3, Session B, Step 1.
  • Losing skip-back captures. [EXIT] before assigning wipes the buffer. Assign first.
  • Wrong stretch algorithm.
  • Chasing the loop. If the SP feeds the Grandmother and the Grandmother feeds the SP, levels must stay low — see Week 3, Session B, Step 2.

What this course could not verify

Flagged honestly rather than guessed at, because getting these wrong wastes a session, not because the rest of the course is any less certain — see the confidence tags throughout for the general picture.

  • Which MIDI adapters, if any, shipped in your SP-404MK2 box.
  • The exact SHIFT+pad combinations for metronome and count-in on your firmware version.
  • Pattern chaining mechanics on your specific firmware — this changed across versions.
  • Whether the Grandmother passes external audio with no key held on your unit, or whether the VCA envelope gates it. Test in Week 3, Session B.
  • The specifics of Public Service Broadcasting's sample clearance arrangements.

This course is a restructuring of a single written guide into a self-paced, cross-linked website — it does not add new claims beyond that source material. Confidence tags (verified, moderate, unverified) are carried over unchanged from the original guide, not reassessed. Menu paths and shortcuts shift between SP-404MK2 firmware versions — check yours via before relying on an exact button sequence.

Hosting & running this site

See the project README.md for full instructions. In short: this is a static site with no build step and no server-side code, so it can be:

  • Deployed to Netlify for free — drag the film-beats-course folder onto app.netlify.com/drop, or connect the repo and set the base/publish directory to film-beats-course.
  • Run locally with a tiny local server (recommended over opening the file directly — see below), e.g. npx serve film-beats-course or python3 -m http.server --directory film-beats-course, then open http://localhost:PORT.
  • Opened directly as a file (double-click index.html) — works for reading, but in most browsers each page opened this way is treated as its own private origin, so the progress checkboxes on one page won't be visible from another. Use the local-server option above if you want progress tracking to work across pages.
